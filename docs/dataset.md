# VitaTwin AI — Dataset Strategy & Provenance

## 1. Data Provenance Disclosure (read first)

VitaTwin AI's Phase 1 demonstration dataset is generated by
`src/data/generate_data.py`, a **rule-based physiological simulator**, not
real patient data and not a resampling of any real dataset.

This is a deliberate, disclosed engineering decision, not an oversight:

- The strongest open datasets combining continuous glucose monitoring (CGM)
  with wearable signals (HR, HRV, steps, sleep) — **OhioT1DM** and
  **D1NAMO** — are hosted on PhysioNet-affiliated infrastructure that
  requires a data-use request and is not reachable from this development
  sandbox's network allowlist.
- Rather than fabricate a claim of using real data, or silently substitute
  a mismatched dataset, VitaTwin AI's dynamic-stream schema is built to be
  **drop-in compatible** with those real datasets. `generate_data.py`
  contains a documented stub, `load_real_dynamic_stream()`, showing exactly
  where a real data loader would plug in without touching any downstream
  code (preprocessing, features, digital twin, models, API, dashboard).
- Every row in every generated table carries a `data_source` column
  (`synthetic`, or `real_proxy` once real data is integrated) so provenance
  is traceable end-to-end, including into the dashboard.

**What this means for evaluation:** treat all reported model metrics in
this project as validated against a synthetic-but-physiologically-informed
dataset, demonstrating methodology and system architecture — not as
clinical accuracy claims. This is stated plainly in `docs/safety.md` and on
the dashboard itself.

## 2. Why Type 2 Diabetes, and the T1D/T2D Dataset Gap

Type 2 Diabetes (T2D) is the challenge-recommended and India-relevant
target condition. However, essentially all open, high-frequency CGM +
wearable datasets (OhioT1DM, D1NAMO) are **Type 1 diabetes** cohorts
(insulin-pump patients), because T1D research populations are the ones
routinely instrumented with research-grade CGM.

VitaTwin AI's chosen approach (**Path 1** from the Phase 0 report):

- **Static/EHR layer**: generated to match a realistic **T2D-relevant
  adult population** (age 35–72, BMI 23–39, HbA1c 5.8–9.8%, 0–18 years
  since diagnosis, medication profile from none → metformin → insulin).
- **Dynamic/wearable layer**: a physiological simulator whose glucose
  response model (meal-driven excursions, circadian baseline, activity-
  linked clearance) is parameterized *by* each synthetic patient's HbA1c
  and BMI — i.e., higher HbA1c patients get larger, slower-clearing meal
  responses, which is directionally consistent with real T2D
  pathophysiology, but this is a **documented modeling assumption**, not a
  clinically validated simulation.

If/when real CGM+wearable data (OhioT1DM, D1NAMO, or a T2D-specific
dataset) becomes accessible, it replaces the dynamic layer only — the
architecture does not change.

## 3. Table Schemas

### `patients.csv`
| column | type | notes |
|---|---|---|
| patient_id | str | e.g. `VT001` |
| age | int | years |
| sex | str | `M`/`F` |
| bmi | float | kg/m² |
| data_source | str | `synthetic` |

### `ehr_records.csv`
| column | type | notes |
|---|---|---|
| patient_id | str | foreign key → patients |
| diagnosis | str | T2D or pre-diabetes, derived from HbA1c |
| diabetes_duration_years | int | |
| hba1c_pct | float | % |
| medication | str | none / metformin / metformin+sulfonylurea / insulin |
| record_date | str (ISO date) | EHR snapshot date |
| data_source | str | `synthetic` |

### `sensor_readings.csv`
| column | type | notes |
|---|---|---|
| patient_id | str | foreign key → patients |
| timestamp | str (ISO datetime) | 5-minute intervals |
| glucose_mgdl | float | simulated CGM reading |
| heart_rate_bpm | float | |
| hrv_ms | float | rMSSD-like proxy |
| steps | int | steps in the 5-minute interval |
| activity_state | str | sleep / sedentary / light / moderate / vigorous |
| is_asleep | bool | |
| data_source | str | `synthetic` |

## 4. Reproducibility

`generate_data.py` is fully seeded (`--seed`, default 42). Same seed +
same config → identical output, verified in `tests/test_generate_data.py`.
Default demo dataset: 8 patients × 14 days × 5-minute resolution = 4,032
readings/patient, 32,256 rows total.

## 5. Known Limitations

- Meal timing/carb-load, activity-state transitions, and sleep windows are
  sampled from documented but non-clinically-derived probability
  distributions — they are plausible, not epidemiologically fitted.
- No inter-day patient state carryover (e.g., no multi-day glycemic drift
  from missed medication) is modeled in Phase 1; this can be added in
  later phases if it strengthens the prediction task.
- The insulin-resistance proxy scales meal-response amplitude and decay
  from HbA1c/BMI using hand-tuned coefficients, not a fitted
  pharmacokinetic model (e.g., Bergman minimal model). This is acceptable
  for a methodology-demonstration PoC and is disclosed here rather than
  presented as clinical simulation.
